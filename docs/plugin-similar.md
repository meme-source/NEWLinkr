# Linkr「找相似」与「找平替」实现逻辑

生成日期：2026-04-25
最近更新：2026-04-27（v3）
文档目的：说明插件内「找相似」和「找平替」应该如何分析当前博主、后台需要调用哪些数据、前端需要展示哪些内容，才能让用户觉得结果可信、易懂、可执行。

---

## 1. 核心定义

### 1.1 找相似

> 这个博主适合我，还有哪些博主在内容、形式、视觉、数据表现上也接近？

### 1.2 找平替

> 哪些博主和当前博主足够像，但预期成本更低、投放效率更好？

### 1.3 二者关系

```text
找平替 = 找相似 + 成本效率排序

具体来说：
1. 找平替先跑一遍找相似，得到候选池
2. 在候选池里设一个相似度门槛（默认 75 分）
3. 通过门槛的候选再按"成本节省 + 数据表现"重排
```

所以「找相似」是基础引擎，「找平替」是它上面的一层成本视角。两个功能共享同一套画像、同一套候选库、同一套硬门槛。

---

## 2. 数据成本分层原则

为了控制成本，所有需要的数据按调用难度和成本分成三层。**优先用前两层，AI 调用只用在前两层算不出来的地方。**

### 2.1 三层定义

| 层级                    | 定义                                                                | 成本                    | 例子                                                           |
| ----------------------- | ------------------------------------------------------------------- | ----------------------- | -------------------------------------------------------------- |
| **Tier 1：基础信息**    | 直接通过 API（Apify / TikHub / 平台公开接口）一次调用拿到的原始字段 | 极低，按次计费          | 粉丝数、帖子标题、播放数、封面 URL、发帖时间                   |
| **Tier 2：换算数据**    | 利用 Tier 1 数据在后端做简单计算/规则匹配得到的派生字段             | 几乎免费                | 中位播放、互动率、活跃天数、邮箱（regex 提取）、hashtag 重叠度 |
| **Tier 3：AI 分析数据** | 必须调用 LLM 或视觉模型才能得到的语义/视觉特征                      | 高，按 token / 图片计费 | 内容主题向量、内容形式标签、视觉调性向量                       |

### 2.2 成本控制策略

1. **Tier 1 数据一次抓全**
   插件触发一次抓取，把后续要用的所有原始字段一次性拿到（粉丝、最近 N 条帖子的所有字段、外链、bio）。**不重复调用 API 拿同一份数据。**

2. **Tier 2 在后端纯算**
   中位播放、ER、活跃天数、hashtag 重叠度这种，全部用 Tier 1 数据在后端 JS/SQL 里算。**不要为这种数据再调 API。**

3. **Tier 3 严格收口**
   每个种子博主一次查询里，AI 调用次数固定：
   - 1 次 bio embedding
   - 1 次最近 N 条内容的 embedding
   - 1 次 LLM 批量打形式标签（N 条一起喂）
   - M 次视觉 embedding（M 由用户设置，0/3/5）
   - **合计 3-5 次 AI 调用，与候选数量无关**

4. **达人库一次入库永久缓存**
   达人库里的博主，所有 Tier 3 字段在入库时算好缓存。**查询时直接取缓存，不重复算。**

5. **粗排用 Tier 2，精排用 Tier 3**
   候选池可能有几万人，全量做 Tier 3 比对成本太高。流程：
   ```
   全库
     ↓ 硬门槛过滤（Tier 1 / Tier 2）→ 几千人
     ↓ 粗排（Tier 2，hashtag 重叠 + 数据量级 + 活跃度）→ Top 300-500
     ↓ 精排（Tier 3，主题向量 + 视觉向量 + 形式标签）→ Top 50
     ↓ 综合 6 维加权 + 去重 + 项目级排除 → Top 20 返回前端
   ```

## 3. 用户可调参数

### 3.1 内容分析帖子数（N）

用户可以自己调整系统分析多少条最近内容。**这个参数同时决定了种子博主从平台抓取的帖子数量。**

| 项   | 值                                  |
| ---- | ----------------------------------- |
| 默认 | 10 条                               |
| 可选 | 5 / 10 / 15                         |
| 上限 | 15 条（再多边际收益低，时间成本高） |

前端文案：

- 「分析最近内容」
- 默认 `10 条`
- 提示 `内容越多，判断越稳，但等待时间会略长。`

后台含义：

- 决定 Tier 1 抓取的帖子数（不会另外抓更多历史）
- 决定"近期内容向量"的样本量
- 不影响"话题身份向量"（那个用 bio）

### 3.2 封面图分析数量（M）

| 项   | 值                 |
| ---- | ------------------ |
| 默认 | 3 张               |
| 可选 | 关闭 / 3 张 / 5 张 |

后台含义：

- 决定走视觉 embedding 的封面图数量
- 关闭时，找相似公式自动按 5 维归一化（详见 §4.5）
- 视觉分析未完成时**不阻塞结果返回**，前端显示"视觉分析中"，完成后异步刷新

### 3.3 过滤项（硬过滤）

```text
只看有邮箱
排除已 No
排除已收藏
只看近期活跃（默认开启）
平台（默认 = 当前博主所在平台，不可改）
国家 / 语言（默认不选 = 不过滤）
最低粉丝数（默认 1000）
最低中位播放（默认 1000）
```

## 4. 找相似 - 完整设计

### 4.1 硬门槛（共 7 项，不进评分，不满足直接踢出）

| 门槛         | 默认值                              | 用户可调                        | 数据 Tier | 字段                   |
| ------------ | ----------------------------------- | ------------------------------- | --------- | ---------------------- |
| 同平台       | 必须相同                            | 否                              | Tier 1    | `platform`             |
| 风险等级     | risk_level ≠ high                   | 否                              | Tier 2    | `risk_level`           |
| 近期活跃     | 30 天内有更新                       | 是（可放宽到 60 天）            | Tier 2    | `recent_active_at`     |
| 粉丝数下限   | ≥ 1000                              | 是（可上调至 5K / 10K / 50K …） | Tier 1    | `followers`            |
| 中位播放下限 | ≥ 1000                              | 是（可上调至 5K / 10K …）       | Tier 2    | `median_views`         |
| 国家 / 语言  | 用户不选 = 不过滤；选了 = 必须匹配  | 是                              | Tier 1    | `country` / `language` |
| 项目级排除   | 已 No / 已收藏 / 已联系，按用户选择 | 是                              | 内部状态  | 项目状态表             |

> **关键点**：粉丝下限和中位播放下限是「防垃圾号」水位（1000 是硬底线），不是「找大号」。如果用户想要腰部以上，自己往上调。这两个下限保留，用户上调，不上调系统不会强行过滤掉小号。

### 4.2 主公式（6 维加权）

```text
找相似得分 =
  内容主题相似度  × 30%
+ 内容形式相似度  × 25%
+ 视觉调性相似度  × 20%
+ 数据量级匹配度  × 15%
+ 近期活跃度      × 5%
+ 可联系性        × 5%
```

每一维都归一到 `0-100`，加权求和后取整，最终得分范围 `0-100`。

视觉关闭或未完成时按 §4.5 规则重新归一化。

### 4.3 维度详解

下面对每一维说明：含义 → 怎么算 → 用什么数据 → 数据来自哪一层（Tier）。

---

#### 维度 1：内容主题相似度（30%）

**含义**：两个博主"在聊什么"的接近度。是 6 维里**最核心**的一维，所以拆成两层（身份 + 近期），抗博主短期主题漂移。

**子公式**：

```text
内容主题相似度 =
  话题身份相似度 × 60%   ← "她是谁"，稳定不变
+ 近期内容相似度 × 40%   ← "她最近在做什么"，动态

[Tier 2 优化层]
hashtag / 关键词 Jaccard 重叠度 → 用于粗排阶段先过滤候选
```

##### 子层 1.1：话题身份相似度（占主题维度的 60%）

| 项               | 内容                                                                    |
| ---------------- | ----------------------------------------------------------------------- |
| 含义             | 博主稳定的人设定位，不随近期内容飘动                                    |
| 怎么算           | 把 bio 文本送入 embedding 模型 → 得到向量 → 算余弦相似度 → 归一到 0-100 |
| 抓什么数据       | bio 原始文本（Tier 1）                                                  |
| 怎么算向量       | OpenAI `text-embedding-3-small`（Tier 3，单次调用 ~$0.00002）           |
| 达人库已有的博主 | `topic_identity_vector` 字段，入库时一次性算好                          |
| 种子博主         | 实时取 bio → 调用 embedding → 缓存到 Redis（24h）                       |
| 退化             | bio 为空或长度 < 20 字符时，该层权重转移给"近期内容层"，即近期层 100%   |

##### 子层 1.2：近期内容相似度（占主题维度的 40%）

| 项               | 内容                                                                              |
| ---------------- | --------------------------------------------------------------------------------- |
| 含义             | 博主最近 N 条帖子的内容方向                                                       |
| 怎么算           | 最近 N 条的 标题 + caption + hashtag 拼接 → embedding → 余弦相似度 → 归一到 0-100 |
| 抓什么数据       | 最近 N 条帖子的标题、caption、hashtag（Tier 1）                                   |
| 数据来自         | 同一次 Apify / TikHub 抓取，与硬门槛和其他维度共用                                |
| 怎么算向量       | OpenAI `text-embedding-3-small`，N 条拼成一个文档算一次（Tier 3）                 |
| 达人库已有的博主 | `topic_recent_vector_n10` 字段（按常用 N 缓存，5/10/15 各一份）                   |
| 种子博主         | 抓回 N 条后即时算 → 缓存到 Redis（24h）                                           |

##### 粗排优化（不影响最终评分，只影响候选过滤）

| 项        | 内容                                                   |
| --------- | ------------------------------------------------------ |
| 含义      | 在精排前用便宜的方式筛掉大量肯定不相关的候选           |
| 怎么算    | 双方 hashtag 集合的 Jaccard 相似度 + topic_tags 重叠度 |
| 数据 Tier | Tier 2（纯字符串集合运算）                             |
| 用法      | 粗排时只保留 Jaccard ≥ 0.05 的候选，再做向量比较       |

##### 主题维度依赖的字段

```text
bio                       // Tier 1
recent_posts.titles       // Tier 1
recent_posts.captions     // Tier 1
recent_posts.hashtags     // Tier 1
topic_identity_vector     // Tier 3，达人库缓存 / Redis 缓存
topic_recent_vector_n     // Tier 3，达人库缓存 / Redis 缓存
topic_tags                // Tier 3 入库时打标，运行时纯比较（Tier 2）
```

---

#### 维度 2：内容形式相似度（25%）

**含义**：博主**怎么呈现**内容。同样是"敏感肌护肤"，可以是真人出镜教程，也可以是图文九宫格，两者投放效果完全不同。

**子公式**：

```text
内容形式相似度 = 形式标签分布的加权重叠度 × 100
```

具体过程：

1. 对每条帖子打多标签，从下面这个标签词典里选 1-3 个
2. 把博主最近 N 条的标签做频次分布
3. 两个博主的分布算加权重叠度

**形式标签词典**：

```text
[Tier 2 规则可推断的标签]
  短视频          // duration < 60s
  长视频          // duration >= 60s
  图文            // 平台元数据 post_type = image_carousel
  教程型          // hashtag/caption 含 "教程"|"how to"|"tutorial"|"步骤"|"step by step"
  开箱            // hashtag/caption 含 "开箱"|"unboxing"|"haul"
  vlog            // hashtag/caption 含 "vlog"|"日常"|"daily life"|"routine"
  测评            // hashtag/caption 含 "测评"|"review"|"评测"|"对比"|"comparison"

[Tier 3 仅 LLM 能判断的标签]
  真人出镜        // 需要看封面或视频帧
  旁白讲解        // 需要语义理解
  字幕主导        // 需要语义理解
  asmr           // 需要音频或语义判断
```

| 项               | 内容                                                                                                                             |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 抓什么数据       | 帖子的 duration、post_type、hashtag、caption（Tier 1）                                                                           |
| Tier 2 推断      | 直接对每条帖子跑规则，不调 AI                                                                                                    |
| Tier 3 推断      | 把 N 条帖子的标题 + caption 一次性塞给 Haiku，让它判断"真人出镜 / 旁白 / 字幕主导 / asmr"中是否有命中。**N 条共用一次 LLM 调用** |
| 达人库已有的博主 | `content_format_tags` 字段，入库时一次性打好                                                                                     |
| 种子博主         | 抓回 N 条后跑规则 + 一次 LLM → 缓存                                                                                              |

**形式维度依赖的字段**：

```text
recent_posts.duration     // Tier 1
recent_posts.post_type    // Tier 1
recent_posts.hashtags     // Tier 1
recent_posts.captions     // Tier 1
content_format_tags       // 数组，达人库缓存 / Redis 缓存
```

---

#### 维度 3：视觉调性相似度（20%）

**含义**：封面图给人的"画面感"是否相似。色调、构图、密度、滤镜风格、是否真人。

**子公式**：

```text
视觉调性相似度 = 平均封面向量的余弦相似度 × 100
```

具体过程：

1. 取双方最近 M 张封面图（M = 用户设置，默认 3，可选 0/3/5）
2. 每张图过视觉 embedding 模型 → 得到向量
3. 把 M 张向量取平均 → 得到博主的"视觉指纹"
4. 两个视觉指纹算余弦相似度

| 项               | 内容                                                                       |
| ---------------- | -------------------------------------------------------------------------- |
| 抓什么数据       | 最近 M 张帖子的封面图 URL（Tier 1）                                        |
| 怎么算向量       | OpenAI `text-embedding-3-small` 的视觉版 / CLIP（Tier 3，每张图 ~$0.0001） |
| 达人库已有的博主 | `cover_image_vector` 字段，入库时算好                                      |
| 种子博主         | 抓帖子时拿到封面 URL → 调用视觉 embedding → 缓存                           |
| M = 0 时         | 该维度不参与，剩 5 维按比例归一化（详见 §4.5）                             |
| 异步策略         | 视觉算完前先用 5 维返回结果，算完后刷新分数                                |

**视觉维度依赖的字段**：

```text
recent_posts.cover_url    // Tier 1
cover_image_vector        // Tier 3，达人库缓存 / Redis 缓存
```

---

#### 维度 4：数据量级匹配度（15%）

**含义**：双方"投放效果"的可比性。不是要粉丝数完全一样，而是中位播放别差太远。

**子公式（中位播放为主轴）**：

```text
ratio = min(候选中位播放, 种子中位播放) / max(候选中位播放, 种子中位播放)
数据量级匹配度 = ratio × 100
```

举例：

- 种子 38K，候选 31K → ratio ≈ 0.82 → 得分 82
- 种子 38K，候选 5K → ratio ≈ 0.13 → 得分 13（多数情况下被中位播放硬门槛先踢了）

**ER 不进核心公式**，只在"同分时的 tiebreak"里用。这样可以避免推一堆"小号天然高 ER"的结果。

| 项               | 内容                                                                         |
| ---------------- | ---------------------------------------------------------------------------- |
| 抓什么数据       | 最近 N 条帖子的 view_count、like_count、comment_count、share_count（Tier 1） |
| 怎么算           | 在后端纯算中位数和比值，**不调 AI**（Tier 2）                                |
| 达人库已有的博主 | `median_views`、`engagement_rate` 字段                                       |
| 种子博主         | 从已抓回的 N 条直接算中位数，不另外调 API                                    |

**数据量级维度依赖的字段**：

```text
recent_posts.view_count       // Tier 1
recent_posts.like_count       // Tier 1
recent_posts.comment_count    // Tier 1
recent_posts.share_count      // Tier 1
median_views                  // Tier 2，达人库缓存
median_likes                  // Tier 2，达人库缓存
median_comments               // Tier 2，达人库缓存
engagement_rate               // Tier 2，达人库缓存
```

---

#### 维度 5：近期活跃度（5%）

**含义**：硬门槛卡了"30 天内有更新"，软分再额外鼓励"最近一周还在发"的博主。活跃博主的合作概率和回复率都更高。

**子公式（阶梯）**：

```text
最后发帖距今天数 d:
  d ≤ 7   → 100
  7 < d ≤ 14  → 70
  14 < d ≤ 30 → 40
  d > 30  → 已被硬门槛踢出
```

| 项               | 内容                                    |
| ---------------- | --------------------------------------- |
| 抓什么数据       | 最近一条帖子的 published_at（Tier 1）   |
| 怎么算           | 后端日期减法（Tier 2）                  |
| 达人库已有的博主 | `recent_active_at` 字段，每次重抓时更新 |
| 种子博主         | 从已抓回的最近一条直接拿                |

**活跃度维度依赖的字段**：

```text
recent_posts.published_at  // Tier 1，取最大值
recent_active_at           // Tier 2，达人库缓存
```

---

#### 维度 6：可联系性（5%）

**含义**：能不能找到联系方式。v1 里故意压得很低，因为找相似的目的是"先告诉你有谁像"，建联是下一步的事。

**子公式（阶梯）**：

```text
email_status = "verified"           → 100
email_status = "found"              → 70
email_status = "missing" 但 bio 有外链 / IG  → 40
完全找不到                           → 0
```

| 项               | 内容                                                                                                                                       |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 抓什么数据       | bio 文本、external_links（Tier 1）                                                                                                         |
| 怎么算           | regex 在 bio 里抓邮箱 + 检查外链是否存在 → 状态字段（Tier 2）<br>邮箱验证可走 Hunter / Snov / Apollo（如果开通了，作为 Tier 1 的可选增强） |
| 达人库已有的博主 | `email_status`、`external_links` 字段                                                                                                      |
| 种子博主         | 实时从 bio + 外链解析                                                                                                                      |

**可联系性维度依赖的字段**：

```text
bio                  // Tier 1
external_links       // Tier 1
email_status         // Tier 2 或 Tier 1（看是否调用第三方验证）
```

### 4.4 实现流程

```text
1. 插件识别当前页面博主
   插件读取：handle, profile_url, 平台, bio, 粉丝数, 头像, 外链
   ↓
2. 后端查询达人库是否已有该博主
   命中：直接读缓存的所有 Tier 1/2/3 字段
   未命中：进入第 3 步即时补数
   ↓
3. 即时补数（仅未命中的种子博主）
   3.1 调用 Apify / TikHub，抓最近 N 条帖子的所有 Tier 1 字段（一次调用拿全）
   3.2 后端纯算 Tier 2 字段：中位播放、ER、活跃度、邮箱
   3.3 调用 AI 算 Tier 3 字段：
        - bio embedding（1 次）
        - 最近 N 条 embedding（1 次）
        - 形式标签 LLM 分类（1 次）
        - M 张封面视觉 embedding（M 次，可异步）
   3.4 缓存到 Redis（24h）
   ↓
4. 候选池粗排（用 Tier 1/2 数据）
   4.1 应用 7 项硬门槛 → 几千个候选
   4.2 计算 hashtag Jaccard + 数据量级 ratio + 活跃度 → Top 300-500
   ↓
5. 候选池精排（用 Tier 3 数据）
   5.1 对 Top 300-500 计算 6 维加权得分
   5.2 视觉维度异步：先用 5 维返回 Top 50，视觉算完后刷新
   ↓
6. 后处理
   6.1 项目级去重（已 No / 已收藏 / 已联系按用户选择排除）
   6.2 取 Top 20
   6.3 为每个结果生成"为什么像"的 3 条理由（用各维度的子分 + 模板填充）
   ↓
7. 返回前端
```

### 4.5 视觉缺失的归一化兜底

当用户关闭视觉分析（M=0）或视觉向量还在异步计算中时：

```ts
// 默认 6 维权重
const weights = {
  topic: 30,
  format: 25,
  visual: 20,
  data: 15,
  activity: 5,
  contact: 5,
};

// 如果视觉不可用，去掉它
const available = visualReady
  ? Object.keys(weights)
  : Object.keys(weights).filter((k) => k !== "visual");

const totalWeight = available.reduce((s, k) => s + weights[k], 0);

// 按比例放大剩余权重到 100%
const score = available.reduce((s, k) => s + (subscore[k] * weights[k]) / totalWeight, 0);
```

**视觉不可用时各维实际权重**：

| 维度     | 默认 | 视觉不可用时 |
| -------- | ---- | ------------ |
| 内容主题 | 30%  | 37.5%        |
| 内容形式 | 25%  | 31.25%       |
| 视觉调性 | 20%  | 0%           |
| 数据量级 | 15%  | 18.75%       |
| 近期活跃 | 5%   | 6.25%        |
| 可联系性 | 5%   | 6.25%        |

体验：先用 5 维返回结果不阻塞，视觉算完后异步刷新分数和排序。前端卡片显示"视觉分析中"的小角标，完成后变绿。

## 5. 找平替 - 完整设计

### 5.1 与找相似的关系

```text
找平替 = 找相似 + 成本效率重排

流程：
1. 跑找相似，得到 Top N 候选（带 6 维子分）
2. 在候选里设相似度门槛（默认 ≥ 75）
3. 计算成本效率字段（Tier 2，纯后端算）
4. 用平替公式重排
5. 返回 Top 20，并给每个结果生成"为什么是平替"和"主要取舍"
```

**关键点**：找平替不重新抓数据、不重新调 AI，**所有新增字段全部用 Tier 1/2 算**。

### 5.2 平替门槛（在找相似硬门槛之上再加）

| 门槛           | 默认值                       | 数据 Tier       |
| -------------- | ---------------------------- | --------------- |
| 综合相似度     | ≥ 75                         | 复用找相似得分  |
| 内容主题相似度 | ≥ 70                         | 复用找相似子分  |
| 中位播放       | ≥ 种子博主中位播放的 30%-40% | Tier 2          |
| 风险等级       | risk_level ≠ high            | Tier 2          |
| 近期活跃       | 30 天内有更新                | Tier 2          |
| 用户过滤项     | 同找相似                     | Tier 1 / Tier 2 |

> 找相似阶段已经踢过一轮，平替门槛主要是「相似度门槛 + 数据下限」，避免推出"看起来像但效果掉太多"的候选。

### 5.3 主公式（4 维加权）

```text
平替分 =
  相似度        × 40%   ← 直接复用找相似得分
+ 成本优势      × 35%
+ 数据表现      × 20%
+ 可联系性/风险 × 5%
```

### 5.4 维度详解

#### 维度 1：相似度（40%）

直接复用找相似得分（0-100），不重新计算。

#### 维度 2：成本优势（35%）

**含义**：候选博主和种子博主比，预计能省多少钱、效率提升多少。

**子公式**：

```text
成本优势 =
  报价节省比例    × 50%
+ CPM 改善比例    × 30%
+ CPE 改善比例    × 20%
```

**报价节省比例**：

```text
saving_ratio = (seed_price - candidate_price) / seed_price
报价节省得分 = clamp(saving_ratio × 100, 0, 100)
```

**CPM（每千次播放成本）**：

```text
candidate_cpm = candidate_price / candidate_median_views × 1000
seed_cpm      = seed_price / seed_median_views × 1000

cpm_improvement = (seed_cpm - candidate_cpm) / seed_cpm
CPM 改善得分 = clamp(cpm_improvement × 100, 0, 100)
```

**CPE（每次互动成本）**：

```text
candidate_cpe = candidate_price / (candidate_median_views × candidate_er)
seed_cpe      = seed_price / (seed_median_views × seed_er)

cpe_improvement = (seed_cpe - candidate_cpe) / seed_cpe
CPE 改善得分 = clamp(cpe_improvement × 100, 0, 100)
```

| 项        | 内容                                                                                  |
| --------- | ------------------------------------------------------------------------------------- |
| 数据 Tier | 全部 Tier 2（纯后端运算）                                                             |
| 输入字段  | `estimated_price_min/max`、`median_views`、`engagement_rate`                          |
| 报价来源  | 达人库 `estimated_price_min/max`（按粉丝量级 + 品类基准估算）；用户回流的真实报价优先 |
| 标注      | 前端必须标"价格为系统估算，建议建联后确认"（除非是真实回流报价）                      |

#### 维度 3：数据表现（20%）

**含义**：候选博主自身数据是不是稳定、有没有掉档风险。

**子公式**：

```text
数据表现 =
  中位播放 / 种子中位播放 × 60%   ← 不能掉太多
+ 数据稳定性               × 30%   ← 播放波动小
+ ER                       × 10%   ← 互动率高
```

**数据稳定性**：

```text
volatility = std(recent_views) / median(recent_views)
数据稳定性得分 = clamp((1 - volatility) × 100, 0, 100)
```

| 项        | 内容                                                             |
| --------- | ---------------------------------------------------------------- |
| 数据 Tier | 全部 Tier 2                                                      |
| 输入字段  | 最近 N 条的 `view_count` 列表、`median_views`、`engagement_rate` |
| 计算时机  | 入库时算好 `volatility_score` 缓存；种子博主即时算               |

#### 维度 4：可联系性 / 风险（5%）

**含义**：找平替阶段更在意"能不能真合作"，所以可联系性 + 风险合并成一个维度。

**子公式**：

```text
可联系性/风险 =
  email_status 阶梯分（同找相似维度 6） × 70%
+ 风险等级阶梯分                       × 30%

风险等级阶梯：
  low      → 100
  medium   → 60
  high     → 已被硬门槛踢出
```

| 项        | 内容                         |
| --------- | ---------------------------- |
| 数据 Tier | Tier 2                       |
| 输入字段  | `email_status`、`risk_level` |

### 5.5 实现流程

```text
1. 跑一次找相似（流程见 §4.4），得到 Top 50 候选 + 6 维子分
   ↓
2. 应用平替门槛（综合相似度 ≥ 75，主题相似度 ≥ 70，中位播放 ≥ seed × 30%）
   ↓
3. 对每个候选计算 Tier 2 字段：
   - candidate_cpm / candidate_cpe
   - 报价节省比例
   - 数据稳定性
   （全部用已有 Tier 1/2 数据，不调 API、不调 AI）
   ↓
4. 按平替公式 4 维加权排序
   ↓
5. 取 Top 20
   ↓
6. 为每个结果生成：
   - "为什么是平替"的 3 条理由（基于成本/数据维度的子分）
   - "主要取舍"的 1-2 条（基于差距维度，例如粉丝量小、合作历史少）
   ↓
7. 返回前端
```

- Apify / TikHub 抓最近 N 条（默认 10）
- Tier 1 / Tier 2 字段全部纯后端算
- Tier 3：bio embedding + 近 N 条 embedding + 形式标签 LLM
- 视觉 embedding 异步（默认 3 张）
- 6 维加权得分 + 7 项硬门槛
- 找平替在找相似之上做成本重排
- 推荐理由 + 主要取舍模板生成

不做：

- 深度受众画像
- 对每个候选逐个调大模型
- 完整历史 ROI 排序
- 实时第三方邮箱验证（默认走 regex + 外链）

### Phase 2：增强可信度

可以加入：

- 视觉向量参与重排（可选打开比例）
- 真实邮箱验证（接 Hunter / Snov）
- 广告帖识别（识别历史合作信号）
- 报价估算校准（按品类 + 国家 + 粉丝段动态调整）
- 用户历史实际报价回流，覆盖估算
- topic_identity_vector 升级：bio + 历史归档（如果运营愿意花成本一次性入库历史）

### Phase 3：数据飞轮

可以加入：

- 实际 CPM / CPE 校准（用户回填 + 自动归因）
- 行业基准（按品类、国家、粉丝量级生成基准值）
- 历史合作 ROI 参与平替排序
- 团队级去重和可靠性评分
- 视觉相似度的多模态扩展（不仅封面，还有内容帧采样）

## 10. 第一版产品口径

对用户解释「找相似」：

> Linkr 会读取当前博主的 bio 和最近 10 条内容，结合视觉调性，从后台达人库里找出主题、形式、视觉、数据表现都接近，并且适合建联的博主。

对用户解释「找平替」：

> Linkr 会先找出和当前博主足够相似的人，再比较预估报价、CPM、互动表现和可联系性，推荐更适合预算敏感项目的替代人选。

对用户解释可调参数：

> 默认分析 10 条内容和 3 张封面，兼顾速度和准确性。你可以提高到 15 条内容、5 张封面让判断更稳定，也可以关闭视觉分析让结果更快返回。

对用户解释下限：

> 默认只看粉丝 ≥ 1000 且中位播放 ≥ 1000 的博主，可以挡掉僵尸号。如果你只想看更大的博主，可以把这两个数字往上调。

## 11. 最终简化公式

**找相似**：

```text
找相似 = 内容主题(30%) + 内容形式(25%) + 视觉调性(20%)
       + 数据量级(15%) + 近期活跃(5%) + 可联系性(5%)

主题维度内部 = 话题身份(60%) + 近期内容(40%)

硬门槛：同平台 + 风险≠high + 30天活跃 + 粉丝≥1000
       + 中位播放≥1000 + 国家语言匹配 + 项目级排除
```

**找平替**：

```text
找平替 = 相似度(40%) + 成本优势(35%) + 数据表现(20%) + 可联系性/风险(5%)

成本优势内部 = 报价节省(50%) + CPM改善(30%) + CPE改善(20%)
数据表现内部 = 中位播放比(60%) + 数据稳定性(30%) + ER(10%)

平替门槛 = 找相似硬门槛 + 综合相似度≥75
        + 主题相似度≥70 + 中位播放≥种子30%
```

**第一版应该追求**：

- 快速返回（Tier 1/2 优先，Tier 3 异步）
- 成本可控（每个种子 3-7 次 AI 调用，与候选数无关）
- 用户看得懂（每个分数有子分，每个推荐有理由）
- 每个结果都有"为什么像"
- 每个平替都有"主要取舍"
- 估算数据明确标注，避免用户误判
